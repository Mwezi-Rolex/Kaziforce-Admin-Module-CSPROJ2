# Digest: Example Report 1 — ICS 410X CS Project II

- **Title:** "Confounder-Robust Machine Learning Model of Voice Biomarkers for Detecting Preclinical Parkinson's Disease" (Jane Doe / 151343, Strathmore University, November 2025).
- **Purpose:** A complete final-year project REPORT (Chapters 1–6 + references + appendices) demonstrating the required format of the ICS 410X Project II documentation.
- **Role:** EXAMPLE REPORT (format/structure model only — its Parkinson's/ML subject matter is NOT a feature source for Kaziforce).

## Structure & format rules

- Front matter order: Title page → Declaration and Approval → Abstract (with Keywords line) → Table of Contents → List of Figures → List of Tables → List of Equations → List of Abbreviations.
- Six chapters, each opening with a numbered "Introduction" section that maps the chapter's remaining sections.
- Chapter titles used: 1 Introduction; 2 Literature Review; 3 Development Methodology; 4 System Analysis and Design; 5 System Implementation and Testing; 6 Conclusions, Recommendations and Future Works; then References; then Appendix (A1…A8, incl. Time Schedules, screenshots, comparative analysis, Turnitin report).
- Chapter 1 sections: Background Information; Problem Statement; Research Objectives (General Objective 1.3.1 + Specific Objectives 1.3.2, roman numerals i–v); Research Questions (mirror the objectives one-to-one); Justification; Scope; Limitations and Delimitations.
- Chapter 2 ends with a Conceptual Framework (figure-driven, input → processing → output pipeline).
- Chapter 3 pairs a Research Paradigm (data acquisition → processing → training → validation) with a Development Approach (here: hybrid Design Thinking + Agile), then System Analysis Diagrams (use case, class, sequence, activity, package), System Design Diagrams (architecture, wireframes), Tools and Techniques, and System Deliverables (one subsection per module).
- Chapter 4 re-presents the diagrams as final figures (numbered 4.x), one section each, minimal prose.
- Chapter 5: Implementation Environment (hardware spec table + software spec table with version and role columns), Dataset Description, Model Training and Evaluation (with numbered equations for metrics), Functional Testing (test-case table: TC-ID, module, description, test data, outcome, verdict), Results and Discussion, GitHub Documentation (repo structure walkthrough).
- Chapter 6: Conclusions; Recommendations; Future Works — prose only, tied back to objectives.
- Referencing: APA-style author-date in-text citations, e.g. (Tougui et al., 2022); full reference list alphabetical with DOIs/URLs.
- Figures/Tables/Equations numbered per chapter (Figure 4.1, Table 5.1, Equation 5.1) and all listed in front matter.
- Abbreviations list format: "ACRONYM – expansion", alphabetical.

## Key content (beyond structure)

- ML web system: Python/Streamlit + MySQL, Random Forest classifier, SHAP explainability, bcrypt auth, functional test table TC-01…TC-09.
- Objectives written as "To analyze/evaluate/design and develop/test and validate…"; research questions mirror them verbatim in structure.
- Scope states in-scope and explicit out-of-scope lists; Limitations vs Delimitations separated.
- Methodology justified by citing literature on the hybrid approach; testing section covers unit, integration, functional (black-box), white-box, k-fold validation, and performance/stress testing.
- Diagram set expected: conceptual framework, methodology process, use case, class, sequence, activity, package, architecture, wireframes per screen.
- Deliverables pattern: System Documentation + one subsection per system module (authentication, core processing, UI).

## Section map

1. Front matter: title, declaration/approval, abstract + keywords, ToC, lists (figures/tables/equations/abbreviations).
2. Ch 1 Introduction: background, problem, objectives (general+specific), questions, justification, scope, limitations/delimitations.
3. Ch 2 Literature Review: intro, current state, challenges, confounders, gaps, conceptual framework.
4. Ch 3 Development Methodology: research paradigm (acquisition/processing/training/validation), hybrid Design-Thinking+Agile approach, analysis diagrams, design diagrams, tools, deliverables.
5. Ch 4 System Analysis and Design: use case, class, sequence, activity, package, architecture, wireframes (final figures).
6. Ch 5 System Implementation and Testing: environment (HW/SW tables), datasets, training/evaluation + metric equations, functional test table, results/discussion, GitHub documentation.
7. Ch 6 Conclusions, Recommendations and Future Works.
8. References (APA author-date, alphabetical, DOIs).
9. Appendices A1–A8: time schedules, screen screenshots, comparative analysis, Turnitin report.
