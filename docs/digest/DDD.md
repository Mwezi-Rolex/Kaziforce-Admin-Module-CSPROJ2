## Immutability & integrity rules

- Audit events, security_events, data_access_logs: append-only; never updated/deleted except controlled retention workflows; older records exported to Object Storage with WORM/object-lock.
- Ledger entries immutable (double-entry); corrections only via reversal/adjustment entries; wallet deletion RESTRICTed while ledger entries exist; balances derived from ledger, never manual updates.
- Contracts immutable after activation except lifecycle transitions; amendments stored separately. Offers: history preserved, changes create new version/negotiation record. Invoices immutable after issuance (corrections via credit notes); tax records immutable once remitted. Financial audit logs append-only.
- Matching/ranking scores immutable per model version + source snapshot (new record, never overwrite). AI fields must carry model version + generation timestamp; AI-inferred data must not overwrite verified data. Embeddings regenerate on source/model change, old kept temporarily.
- Notification delivery logs append-only; templates immutable after approval (new versions). Timesheet approvals append-only (reversal = new event). Support assignment history append-only. Knowledge published versions immutable; workflow actions append-only. Agent audit events and memory audit events append-only.
- Facts/raw_events in ClickHouse immutable; corrections via compensating events. Consent records versioned.
- Soft delete standard: deleted_at on all core tables; no physical delete unless retention/legal/privacy requires; credentials never physically deleted once used in decisions; expired certifications retained.
- Standard audit fields on all business-critical tables (created_at/updated_at/deleted_at/created_by/updated_by/deleted_by/version/metadata); audit fields never replace immutable audit event tables; every critical state change emits an audit event.
- UUID PKs (v7 preferred, v4 acceptable), immutable, never change; business identifiers not PKs; sequential IDs avoided for external entities.
- FKs only within a service database; cross-service references stored as UUIDs validated via APIs/events/read models; no cross-service DB joins. FKs must be indexed.
- Cascade policy: minimal destructive cascades — RESTRICT for financial/compliance (Wallet→Ledger, Contract→Timesheets), CASCADE only for short-lived dependents (User→Sessions/MFA), NO ACTION default; ON UPDATE NO ACTION.
- Retention jobs must honor legal holds (messages under hold never deleted). Deletion of notifications/queues etc. per retention matrix (audit/finance 5–7+ years; financial ledger retained where legally required; erasure exceptions for litigation/fraud/tax).
- Redis never the source of truth for financial/transactional data; cache keys tenant-prefixed; write-behind banned for finance/compliance/identity/audit.
- Idempotency: payment provider callbacks idempotent (ledger posted once); gateway-level idempotency via Redis (TTL 24h) + api_idempotency_audit; key reuse with different payload → 422 conflict (per FR-ERR-005).
- PCI DSS: never permanently store CVV/CVC, magnetic stripe, PIN, PIN blocks; prefer tokens.
- Migrations (Flyway/Liquibase, V{n}__Name.sql) immutable after release; manual production schema changes prohibited; every migration peer-reviewed and traceable to SRS/TDD.
- Passwords never plaintext (Argon2id, BCrypt fallback); API keys hashed; OAuth tokens encrypted; recovery codes encrypted; all backups encrypted (AES-256 at rest, TLS 1.3 in transit); RLS tenant_id policy on tenant-owned tables; tenant_id NOT NULL on tenant-owned records.

## Hard constraints (data layer musts / must-nots)

- Every table: UUID PK; tenant_id on tenant-scoped tables; created_at/updated_at TIMESTAMPTZ (never TIMESTAMP); soft delete via deleted_at; version column for optimistic locking.
- Money: NUMERIC (never float), NUMERIC(18,4) standard; percentages/scores NUMERIC(8,4); CHECK(amount >= 0), net = gross − fee − tax; CHECK(tenant_id IS NOT NULL).
- snake_case naming; plural tables; `_id` PKs, `_at` timestamps, `_date` dates, `_status`/`_type` fields, is_/has_/can_/requires_ booleans; idx_/uq_/fk_/chk_/vw_/mv_/trg_ prefixes.
- Enums uppercase, stored via PG enum/lookup/app validation; no free-text statuses; historical enum values preserved; do not reuse one enum across workflows.
- Defaults must not create valid financial transactions without explicit business action; approval/verification/payment statuses default to non-final states.
- Validation at API, service, domain, and DB layers; expiry_date >= issue_date, end >= start, confidence 0–1, allocation 0–100; file size/MIME allowed-list.
- Cross-service: no DB-level FKs, no cross-service joins; validate via API lookup, event-synchronized read model, cached reference data, or saga orchestration.
- Denormalize only display/dashboard/search data; never denormalize financial source-of-truth, audit, compliance, or ledger records.
- Security: RLS on tenant tables; column-level security + dynamic masking for PII (national ID, salary, bank accounts); least privilege; keys/secrets centrally managed, never hardcoded, never in Git; secrets isolated per environment; MFA for admin access.
- Retention: audit logs 5–7 years, financial records 7 years (2,555 days), auth logs 730 days, chat 365 days (anonymize before delete), KYC 1,825 days — seeded into data_retention_rules; archive/anonymize flags per Sec 51.4.
- Performance targets: PK lookup ≤10ms P95, indexed query ≤30ms, complex ≤100ms, search ≤200ms, vector ≤300ms; DB availability ≥99.95%; RPO ≤15 min, RTO ≤1 hour; cache hit ≥90%.
- AI data: only approved, active models in production; every AI artifact traceable to model version + source data; feature values versioned; explanation payload required for hiring-influencing scores; memory access restricted to permitted scopes.
- Governance: every DB object traceable to an approved SRS/TDD requirement (no orphan objects); all schema changes via version-controlled migrations; constraints/indexes documented in Data Dictionary/Constraint Catalog/Index Catalog.
