## Structure used

1. Front matter: cover, declaration/approval, abstract, table of contents and lists.
2. Chapter 2: literature/current systems, proposed system and conceptual framework.
3. Chapter 3: system development methodology, prototyping model, justification, system analysis, functional and non-functional requirements, tools/techniques, domain of execution and deliverables.
4. Chapter 4: system analysis, design and architecture, including use-case and sequence diagrams.
5. Chapter 5: system implementation and testing, including test descriptions, performance evaluation, test data/results, discussion and page screenshots.
6. Chapter 6: conclusion, recommendations and future work.
7. References and appendices: time schedule, user guide, browsing/claiming screens, GitHub repository, system settings, Turnitin report.

## Patterns worth reusing

9. Chapter 3 explicitly separates functional and non-functional requirements before tools and deliverables.
10. Chapter 5 separates test description, performance/model evaluation, test data and results discussion.
11. Screenshots are used as implementation evidence for home, login, user panel, report form, admin panel and item-viewing screens.
12. Appendices include user-guide, repository and settings evidence plus originality evidence.
13. This is a lost-and-found/AI project example; its domain content does not transfer, but the documentation skeleton does.
